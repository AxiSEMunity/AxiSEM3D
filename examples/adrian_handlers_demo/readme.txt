Adrian Handlers Demo
====================
A companion example demonstrating the two main output handlers provided by the
external `axikernels` package:

  StationOutput   – reads per-rank NetCDF waveforms, exposes them as ObsPy
                    streams, and can obspyfy the output (miniSEED + StationXML
                    + QuakeML).
  ElementOutput   – reads the full wavefield at GLL points and interpolates at
                    any [radius, lat, lon] coordinate.

This is a companion example: AxiSEM3D runs the simulation as usual, and
`axikernels` handles all post-processing.  The output-handler functionality is
NOT built into AxiSEM3D itself.


Validated scope
---------------
  - 1-D PREM anisotropic model (50 s mesh)
  - GSN small station set
  - Single isotropic moment-tensor source (QuakeML origin from
    HANDLERS_EXAMPLE_cat.xml)
  - StationOutput: waveform access and obspyfication
  - ElementOutput: wavefield interpolation at arbitrary [r, lat, lon]


External dependency
-------------------
This companion example requires the `axikernels` Python package.  It is not
part of AxiSEM3D itself.

The package lives at:

  https://github.com/Adrian-Mag/AxiSEM3D_Kernels.git

Clone the axikernels repository alongside the AxiSEM3D repository so that
you end up with:

  some_folder/
  ├── AxiSEM3D/              ← this repository (cloned from AxiSEMunity)
  │   └── examples/
  │       └── adrian_handlers_demo/   ← you are here
  └── AxiSEM3D_Kernels/      ← axikernels (cloned from Adrian-Mag)

From this example directory the axikernels repo is then at:

  ../../../AxiSEM3D_Kernels

Installation (conda — recommended):

  conda env create -f ../../../AxiSEM3D_Kernels/environment.yml
  conda activate axikernels_env
  pip install -e ../../../AxiSEM3D_Kernels

Or with pip only (into any Python ≥ 3.9 environment):

  pip install -e /path/to/AxiSEM3D_Kernels

See the axikernels README for full requirements.


Quick start
-----------
1.  Install axikernels (see above).

2.  Build AxiSEM3D and copy the compiled binary into this folder (or put it on
    PATH):

        cp /path/to/build/axisem3d .

    This example does NOT ship a pre-built binary.

3.  Run the simulation:

        bash run.sh

    To use more MPI ranks:

        NRANKS=4 bash run.sh

    Output will be written to sim_run/output/:
      sim_run/output/stations/GSN_Station_Grid/
      sim_run/output/elements/mantle/

4.  Run the post-processing notebook:

        jupyter notebook handlers_demo.ipynb

    The notebook walks through:
      a. Loading station waveforms with StationOutput
      b. Obspyfying the output (miniSEED + StationXML + QuakeML)
      c. Interpolating the wavefield with ElementOutput

5.  Clean up:

        bash clean.sh


Validation status
-----------------
This example was validated in March 2026 using:

  - bash run.sh  (2 MPI ranks)
  - Full notebook workflow with handlers_demo.ipynb

Validated configuration:
  - Mesh: global_mesh__prem_ani__50s.e (PREM anisotropic, 50 s)
  - Station file: GSN_small.txt
  - Source: HANDLERS_EXAMPLE_cat.xml
  - axikernels handlers: StationOutput, ObspyfiedOutput, ElementOutput

The solver binary used for validation was the locally built upstream binary.
Build that binary using the normal AxiSEM3D build instructions.
The committed notebook is intentionally output-free; run it from this example
directory after `bash run.sh` to regenerate the figures and printed output.


Running options
---------------
  bash run.sh --help        Show usage and exit (no binary required).
  bash run.sh --dry-run     Validate input files only; report what would run.
  bash run.sh               Full run (requires binary and MPI).
  NRANKS=4 bash run.sh      Use 4 MPI ranks.


Input files
-----------
  input/   – AxiSEM3D inparam YAML files, mesh, station list, and source
             catalogue used for this demo simulation.


Notes
-----
  - sim_run/ and output/ are gitignored (generated by run.sh).
  - bash clean.sh removes generated output (with confirmation).
  - Computational cost for the default setup (50 s mesh, 2 MPI ranks) is
    modest relative to production runs; expect a few minutes on a workstation.
  - The axisem3d binary is linked against the MPI library from the build
    environment.  Make sure the same conda environment (or at least its
    mpirun) is active when running the simulation.  run.sh automatically
    prefers $CONDA_PREFIX/bin/mpirun over the system-wide launcher.


Integration note
----------------
This example is deliberately packaged as a companion example, not as evidence
that the axikernels handlers are integrated into AxiSEM3D core.

What is demonstrated here:
  - AxiSEM3D produces station and element output in the standard NetCDF format.
  - The external package axikernels can read that output via StationOutput and
    ElementOutput and expose it through a Python API.

What remains outside the scope of this example:
  - General in-core post-processing support within AxiSEM3D itself
  - Broad coverage of output formats and handler configurations
  - Full replacement of the exploratory notebook-based workflow
